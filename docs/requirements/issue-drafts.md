## 3. 各 Issue 验收标准

### Issue #16 用户、角色与基础权限（v0.1）

关联：US-24、REQ-06

1. Given 未登录用户，When 访问需要登录的页面或接口，Then 返回 401 并跳转登录页。
2. Given 参与者身份，When 调用组织者或平台运营者专属接口，Then 返回 403 并记录审计信息。
3. Given 平台运营者身份，When 访问运营接口，Then 正常返回结果。
4. Given 普通注册用户首次登录，When 尚未选择角色，Then 不能执行发布或报名操作。

### Issue #17 参与者偏好档案（v0.1）

关联：US-01、REQ-03

**范围调整**：本 Issue 只交付偏好档案维护；报名表单预填与信息复用随报名功能，在 v0.2 由 #21 承接。原 Issue 正文中的报名预填类验收标准需要移到 #21。

1. Given 参与者尚未填写档案，When 打开偏好设置，Then 显示兴趣、技能、可参与时段三个分区，并标明哪些必填。
2. Given 填写完整并保存，When 重新登录，Then 回显上次保存的内容。
3. Given 删除某个兴趣标签，When 保存成功，Then 该标签不再参与后续匹配。

### Issue #18 调研与志愿活动的统一发布模板（v0.1）

关联：US-05、REQ-02

1. Given 组织者选择「调研」或「志愿」模板，When 进入发布页，Then 显示该类型的必填字段清单（资格、时间、地点、时长等）。
2. Given 任一必填字段为空，When 提交发布，Then 拒绝发布并定位到缺失字段。
3. Given 发布成功，When 参与者查看详情，Then 展示内容与模板字段一一对应，没有多余字段。

### Issue #19 机会检索与详情展示（v0.1）

关联：US-03、US-04、REQ-01、REQ-04、REQ-05

1. Given 新注册的参与者，When 进入机会列表，Then 能看到全部已发布且未截止的调研与志愿机会。
2. Given 选择类型、时间范围或输入关键词，When 应用筛选，Then 只展示符合条件的机会。
3. Given 筛选条件没有任何匹配，When 应用筛选，Then 显示空状态提示，而不是报错或空白页。
4. Given 组织者未填写某个必填字段，When 参与者打开详情，Then 该字段显示「未提供」。
5. Given 活动已过报名截止时间，When 参与者打开详情，Then 显示截止状态并禁用报名入口。

### Issue #20 资格匹配与匿名定向邀请（v0.2）

关联：US-06、US-07、REQ-07、REQ-17

1. Given 参与者档案完整，When 打开「适合我的机会」，Then 只显示资格满足且可参与时段有交集的机会。
2. Given 某机会的资格不满足，When 参与者浏览匹配列表，Then 该机会不出现，但仍可在全量列表中检索到。
3. Given 某个机会与已确认的参与时间冲突，When 参与者浏览匹配列表，Then 该机会标注冲突原因。
4. Given 活动名额未满，When 组织者打开候选池，Then 只显示匿名摘要（年级、专业、技能标签），不显示姓名、手机号和微信号。
5. Given 组织者选中候选并发出邀请，When 邀请创建成功，Then 邀请出现在受邀者的「我的邀请」列表，并带有有效期。
6. Given 受邀者打开「我的邀请」，When 接受邀请，Then 直接生成报名并锁定名额，不需要重新填写档案。
7. Given 受邀者拒绝或邀请过期，When 系统处理该邀请，Then 名额释放，且不在受邀者侧留下任何负面记录。

**依赖调整**：v0.2 的邀请结果通过「我的邀请」列表呈现，不依赖 v0.3 的 #26 通知能力。

### Issue #21 报名、名额锁定与取消（v0.2）

关联：US-08、US-09、US-02、REQ-08、REQ-03

1. Given 名额有剩余且资格满足，When 提交报名，Then 报名状态为已确认，剩余名额减 1。
2. Given 名额已满，When 提交报名，Then 拒绝报名并提示可以加入候补。
3. Given 两人同时争抢最后一个名额，When 两人都提交报名，Then 只有一人状态为已确认，另一人收到「名额已满」。
4. Given 参与者档案完整，When 打开报名表单，Then 预填年级、专业、空闲时间和联系方式，且本次报名可单独修改。
5. Given 在报名表单中修改了预填值，When 提交报名成功，Then 档案中的值保持不变。
6. Given 档案缺少报名必填项，When 提交报名，Then 拒绝提交并提示需要补齐的字段。
7. Given 报名已确认且活动尚未开始，When 取消报名，Then 状态变为已取消，名额立即释放。
8. Given 活动已经开始，When 尝试取消，Then 拒绝自行取消并提示联系组织者。

### Issue #22 候补队列与自动补位（v0.2）

关联：US-10、US-11、REQ-09

1. Given 名额已满，When 点击「加入候补」，Then 进入队列并获得一个可见的排队序号。
2. Given 已在同一活动的候补队列中，When 再次点击加入，Then 提示已在队列中，不重复入队。
3. Given 参与者在候补队列中，When 主动退出候补，Then 从队列移除，后续候选人的序号相应前移。
4. Given 候补队列非空，When 一名已确认参与者取消报名，Then 系统按序号把第一顺位转为已确认。
5. Given 补位成功，When 该参与者打开「我的报名」，Then 该条记录显示为已确认。
6. Given 第一顺位在有效期内未确认，When 有效期到期，Then 系统顺延给下一顺位，并记录顺延原因。
7. Given 补位完成，When 组织者打开活动名单，Then 名单人数与状态已同步更新。

**依赖调整**：v0.2 的补位结果通过「我的报名」与名单呈现，不依赖 v0.3 的 #26 通知能力。

### Issue #23 GitHub OAuth 登录（v0.2）

关联：US-23、REQ-10

1. Given 未登录用户，When 选择 GitHub 登录，Then 跳转授权页，回调成功后建立会话。
2. Given 首次登录完成授权，When 进入平台，Then 要求补充角色和必要档案，未完成前不能报名。
3. Given 用户拒绝授权或回调失败，When 返回平台，Then 停在登录页并提示，不创建账号。
4. Given 授权账号邮箱不可见，When 系统尝试读取邮箱，Then 提示绑定邮箱或改用邮箱注册。

### Issue #24 签到与完成确认（v0.3）

关联：US-12、US-13、REQ-16

1. Given 活动进行中，When 组织者打开签到名单，Then 只显示状态为已确认的参与者。
2. Given 组织者勾选某人到场，When 保存签到，Then 记录签到时间；未勾选者在活动结束后标记为缺席。
3. Given 活动结束，When 组织者提交完成确认，Then 只有已签到的参与者被记为完成，未签到者不产生完成记录。
4. Given 活动已结束，When 参与者打开「我的报名」，Then 每条记录显示已完成、缺席或待确认。

### Issue #25 参与记录查看与引用（v0.3）

关联：US-14、US-15、REQ-11

1. Given 参与者有已完成记录，When 打开「我的参与记录」，Then 按时间倒序列出活动名称、类型、时间、担任角色和组织者。
2. Given 调研和志愿记录都有，When 打开「我的参与记录」，Then 两类出现在同一列表，并支持按类型筛选。
3. Given 没有任何记录，When 打开「我的参与记录」，Then 显示空状态和引导说明。
4. Given 选中某条参与记录，When 点击「生成摘要」，Then 输出活动名称、时间、角色、组织者的纯文本摘要。
5. Given 选择时间范围，When 导出，Then 文件只包含本人记录，不含其他参与者信息。
6. Given 记录对应的活动被组织者撤销，When 再次查看该记录，Then 标注为已失效，但保留在历史中。

### Issue #26 站内通知与邮件通知（Outbox）（v0.3）

关联：US-16、US-17、REQ-13

1. Given 关键事件发生（报名确认、取消、候补递补、完成确认），When 事件处理成功，Then 相关方收到对应的站内通知。
2. Given 存在未读通知，When 打开平台任意页面，Then 通知入口显示未读数量。
3. Given 打开通知并标记已读，When 已读状态保存成功，Then 未读数量相应减少。
4. Given 用户开启邮件通知且邮箱已验证，When 关键事件发生，Then 通过 Outbox 异步发送邮件，主流程不等待发送结果。
5. Given 邮件服务不可用，When 触发关键事件，Then 报名、取消、候补事务照常提交，邮件进入待重试状态。
6. Given 同一事件被重复触发，When 该事件进入发送队列，Then 幂等键保证只发送一次。
7. Given 连续失败超过阈值，When 运营者打开发送记录，Then 能看到失败列表和失败原因。

### Issue #27 字段级隐私授权与导出审计（v0.3）

关联：US-20、US-21、REQ-12

1. Given 尚未确认参与，When 其他参与者查看活动详情或名单，Then 看不到手机号、微信号和家庭住址。
2. Given 已确认参与，When 其他参与者查看名单，Then 仍然看不到联系方式。
3. Given 已确认参与，When 该活动组织者查看名单，Then 只可见必要联系方式。
4. Given 活动结束超过设定的保留期，When 组织者查看该活动名单，Then 联系方式自动失效。
5. Given 无导出权限，When 打开名单页面或直接调用导出接口，Then 不显示导出入口，接口返回 403。
6. Given 有权限，When 完成一次导出，Then 记录操作人、时间、字段范围和记录条数。
7. Given 访问不属于自己负责活动的名单，When 提交请求，Then 拒绝访问并写入审计日志。

### Issue #28 活动审核、举报与运营统计（v0.3）

关联：US-18、US-19、REQ-18、REQ-19

**证据状态**：F-11（运营侧缺少治理手段）已在 `findings.md` 补登，证据为 A1-Q1、A1-Q2、A1-Q3、A1-Q8、A1-Q9、A2-Q8。

1. Given 组织者提交发布，When 活动进入待审核状态，Then 运营者能看到模板字段完整性检查结果。
2. Given 信息不全或疑似虚假，When 运营者驳回，Then 组织者收到带原因的驳回通知，活动不对外展示。
3. Given 收到举报，When 运营者处理完成，Then 记录处理人、时间、结论，可回溯。
4. Given 两个活动内容高度相似，When 运营者审核新发布，Then 系统提示疑似重复发布，由运营者判断。
5. Given 选择时间范围，When 查询统计，Then 展示报名人数、到场率、活动类型分布和各年级参与比例。
6. Given 打开任一统计视图，When 页面加载完成，Then 不出现姓名、学号、手机号。
7. Given 某个维度的样本量小于设定阈值，When 查询该维度，Then 不展示该维度数值。

### Issue #29 活动详情页问答（v0.3）

关联：US-22、REQ-14

1. Given 活动开放提问，When 提交问题，Then 问题出现在详情页，且不展示提问者的联系方式。
2. Given 组织者回复，When 回复发布成功，Then 提问者收到通知。
3. Given 活动报名已截止，When 参与者尝试提交新问题，Then 不再接受新问题，历史问答仍可查看。

### Issue #33 线上问卷链接入口（v0.1）

关联：US-25、REQ-15

按项目基线，平台**不接收也不保存问卷题目与答卷**，只保存链接与目标人群。

1. Given 组织者选择「调研」类型，When 在发布表单中填写有效的问卷链接，Then 发布成功且详情页显示问卷入口。
2. Given 问卷链接不是 http/https 格式，When 组织者提交发布，Then 拒绝发布并提示修正链接。
3. Given 机会已配置问卷链接，When 目标人群内的参与者点击入口，Then 跳转到外部问卷页面，平台不接收也不保存答案。
4. Given 参与者不在目标人群内，When 查看该机会，Then 不显示问卷入口。

### Issue #34 活动编辑、下架与撤销（v0.2）

关联：US-26、REQ-02、REQ-11

1. Given 活动已发布且未开始，When 组织者修改时间或地点，Then 详情页更新，已报名者能看到变更记录。
2. Given 活动已下架，When 参与者访问详情，Then 显示已下架，不再接受新报名。
3. Given 活动被撤销，When 已确认参与者打开「我的报名」，Then 显示活动已取消。
4. Given 活动被撤销，When 参与者查看参与记录，Then 原记录标注「已失效」但保留。
5. Given 活动已开始，When 组织者尝试撤销，Then 拒绝并提示需线下处理。

### Issue #35 同一时段重复报名拦截（v0.2）

关联：US-08、REQ-08、REQ-20

1. Given 参与者已确认活动 A（14:00–16:00），When 报名时间重叠的活动 B，Then 拒绝并提示与 A 冲突。
2. Given 参与者已确认活动 A（14:00–16:00），When 报名 18:00–20:00 的活动 C，Then 报名成功。
3. Given 报名被冲突拒绝，When 参与者取消活动 A 后重新报名 B，Then 报名成功。
4. Given 参与者在候补队列中，When 报名时间重叠的另一活动，Then 允许报名，但补位时再次校验冲突。

### Issue #36 [NFR] 预约并发与性能验证（v0.2）

关联：US-03、US-08、REQ-08、NFR-P-01 ~ P-04

1. Given 某活动剩余 10 个名额，When 50 个用户并发提交报名，Then 成功 10 条、失败 40 条，且无超员。
2. Given 同一用户并发提交两次报名，When 两次请求都到达，Then 只产生一条已确认记录。
3. Given 机会列表有 500 条数据，When 连续请求 100 次，Then P95 响应时间不超过 800ms。
4. Given 报名接口在 20 QPS 下运行 5 分钟，When 统计响应时间，Then P95 不超过 500ms 且错误率低于 0.1%。

### Issue #37 [NFR] 个人隐私保护与信息复用边界（v0.3）

关联：US-02、US-20、US-21、REQ-03、REQ-12、NFR-S-01 ~ S-05

1. Given 参与者尚未确认参与，When 任一角色通过接口查询该活动报名者，Then 响应中不含手机号、微信号、家庭住址。
2. Given 参与者报名某活动，When 表单自动回填，Then 只出现该活动模板要求的字段，其余档案字段不出现在请求中。
3. Given 已确认参与的参与者，When 非该活动的组织者查询名单，Then 返回 403 并写入审计日志。
4. Given 活动结束并超过保留期，When 组织者打开名单，Then 联系方式列为空，且系统提示已过期。
5. Given 一次名单导出完成，When 查询审计记录，Then 能看到操作人、时间、字段范围与条数。

### Issue #38 [NFR] 可用性与外部依赖容错（v0.3）

关联：US-17、US-23、REQ-10、REQ-13、NFR-A-01 ~ A-05

1. Given 邮件服务不可用，When 参与者提交报名，Then 报名成功返回，邮件进入待重试状态。
2. Given 邮件服务恢复，When 重试任务执行，Then 待发邮件全部投递，失败项在运营后台可见。
3. Given 同一报名事件被重复触发，When 发送流程执行两次，Then 实际只投递一封邮件。
4. Given GitHub 授权回调超过 10 秒，When 用户返回平台，Then 提示授权超时并可重试，不创建残缺账号。
5. Given 邮件队列积压超过阈值，When 访问健康检查接口，Then 返回降级状态而不是正常。
