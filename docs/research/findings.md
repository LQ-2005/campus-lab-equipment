## 4. 主要发现

> 每条发现严格区分**事实**、**用户原话**、**团队推断**。所有发现关联至少一个访谈证据编号（如 `S1-Q4`）。原 7 个假设（H1–H7）作为验证基准。

### F-01 机会入口依赖微信群，新人或未入群者被完全排斥

- **事实**：
  - 所有 9 位受访者确认，活动信息 100% 来自微信群
  - S1 作为新同学，得知研愿群的渠道是**同学口头告知**（非公开渠道），不在任何调研/志愿群 → 完全不知道有活动
  - O3 问卷只能靠自己朋友圈 + 认识的群 → 样本偏倚、数量不足
- **用户原话**：
  - S1：「志愿活动目前大多在微信群里发，但是一开始或者"从 0 到 1"的新人没有这些渠道获取，可能不在对应的微信群里的同学更无从谈起参加了」
  - O3：「我们一般都是自己发朋友圈让认识的同学填，这导致很多调查不够随机，样本数量不够」
- **团队推断**：
  - 微信群模式本质上是"信息孤岛"——不在群 = 完全失联
  - 这不仅对新人不公平，也限制了组织者的招募范围和问卷样本质量
  - H1 已验证：信息分散是平台最需要解决的根本问题
- **证据**：`S1-Q2`、`S1-Q4`、`O3-Q3`、`O3-Q19`
- **关联假设**：H1 ✅ 已验证

### F-02 微信群消息无主动推送，有意愿但错过名额是高频痛点

- **事实**：
  - S2 明确说"有意参加但总是因为信息无法及时传达导致没有名额"
  - 微信群消息被淹没是微信群固有限制（群多、免打扰、消息频率高）
- **用户原话**：
  - S2：「各种调研或者志愿活动很抢手，可能因为微信群无提醒导致有意参加但是总是由于信息无法及时传达导致"没有名额"，希望可以有更多的"提醒"」
  - S2：「希望可以有更多的"提醒"」
- **团队推断**：
  - "有意愿但错过"不是参与者的过错，是传播渠道的问题
  - 平台需要提供不依赖"刷群"的通知机制
  - H1（信息分散）和 H7（需要主动通知）都涉及
- **证据**：`S2-Q5`、`S2-Q11`、`S2-Q20`、`S2-Q24`
- **关联假设**：H1 ✅ 已验证 + H7 ✅ 已验证

### F-03 基础身份/时间信息在不同活动问卷中重复填写

- **事实**：
  - S3 过去一学期 5+ 次报名，每次都要重新填年级、专业、空闲时间段、联系方式
  - O1、O2 的报名表中这些字段基本一致
- **用户原话**：
  - S3：「经常会有最基本的信息反复填写在报名问卷上，导致有些麻烦耽误时间」
  - S3：「如果能维护一次固定的信息档案就好了」
- **团队推断**：
  - 参与者愿意维护一次信息档案（偏好 + 技能 + 空闲时间）用于持续报名
  - 组织者也希望报名者的基础信息能自动填充
  - H5 已验证：统一偏好档案是双方共同需求
- **证据**：`S3-Q10`、`S3-Q10`（原话二）
- **关联假设**：H5 ✅ 已验证

### F-04 资格和关键信息发布时不透明，导致参与者因信息不全不敢或尴尬参与

- **事实**：
  - S4 报了志愿活动后才发现时间冲突 → 被刷下来很尴尬
  - S4 内向，因为不确定自己合不合适而不敢报新活动
  - O1 曾因公告漏写"需要穿运动鞋"导致参与者无法参与
- **用户原话**：
  - S4：「很多调研和志愿活动现在对要求不太明显，我比较想参与但我怕到时候不够资格，或者时间冲突等因素被刷下来很尴尬」
  - O1：「某次公告漏写了"需要穿运动鞋"，导致有参与者穿皮鞋来无法参与」
- **团队推断**：
  - 这是**原 7 个假设之外的新发现**
  - "信息不透明"不仅造成效率问题（反复确认），还对谨慎型/内向型用户造成社交压力
  - 发布时的模板强制字段（资格、具体时间、地点、时长、服装要求）能在发布端从源头减少这个问题
  - A1 的"希望发布格式标准"从运营侧印证了这个发现
- **证据**：`S4-Q7`、`S4-Q8`、`O1-Q5`、`A1-Q6`
- **关联假设**：新发现（原 H 假设未覆盖）

### F-05 参与后无统一记录出口，只能靠微信群回忆

- **事实**：
  - S5 填申请材料时需要回忆过去的参与经历 → 翻微信群聊天记录 → 花 15 分钟凑齐
  - S5 有 2 次活动公告被撤回，根本找不到记录
  - 所有组织者（O1、O2）均无"完成记录"的正式流程，只有现场签到纸质名单
- **用户原话**：
  - S5：「参与过后，调研和志愿活动记录不太方便查找。比如在一些其他方面需要填写这些经历时，只能一个个根据微信群名来回忆自己的所做」
  - S5：「希望保存的信息：活动名称、时间、角色、组织者」
- **团队推断**：
  - 调研和志愿活动的记录都需要统一出口
  - "参与记录"不仅是调研需要，志愿活动同样需要（用于奖学金申请、履历填写）
  - H6 已验证：两类活动的参与记录可统一管理
- **证据**：`S5-Q18`、`S5-Q19`
- **关联假设**：H6 ✅ 已验证

### F-06 参与者需要预沟通渠道，但"加好友"模式效率极低

- **事实**：
  - S6 有参与意愿但公告信息不足以判断自己是否适合 → 想多问 → 加组织者微信被拒
  - S6 最后硬着头皮报了，参与时发现内容与预期不符
- **用户原话**：
  - S6：「微信群里发的调研/志愿公告就算明确了参与资格注意事项等信息，我可能还有些个人问题需要问一下老师，但是目前只能加好友，而一般老师很忙不会同意，所以很难有一对一的预沟通渠道」
  - S6：「希望有某种不用加好友就能问问题的渠道」
- **团队推断**：
  - 这是**原 7 个假设之外的新发现**
  - "预沟通渠道"的核心矛盾：参与者有个性化疑问 → 公告写不完整/不想写 → 组织者被烦 → 最终要么不报要么硬着头皮报
  - 解决方案可能是：活动详情页设置"问答/评论区"，组织者可选择性回复
  - 此功能优先级：v0.1 可暂缓（不是核心阻塞项），v0.2 考虑
- **证据**：`S6-Q6`、`S6-Q20`
- **关联假设**：新发现（原 H 假设未覆盖）

### F-07 组织者每次重写招募文档，需要统一发布模板

- **事实**：
  - O1 每次组织活动都从头写公告文案和报名表字段
  - A1 作为审核方，也希望活动发布格式更标准
  - 质量参差不齐：O1 曾漏写"穿运动鞋"，S4 遇到过时间不透明
- **用户原话**：
  - O1：「每次招募需要自己重新写一份"报名文档"，要是有一个统一的可自由选择的模板格式使用就好了」
  - A1：「希望活动发布时能有更标准的格式，减少反复沟通」
- **团队推断**：
  - 这是**原 7 个假设之外的新发现**
  - 模板能从源头解决 F-04（信息不透明）、F-05（重复报名字段）等多个问题
  - 模板应区分"调研"和"志愿"两类，每类设必填字段（资格、具体时间、地点、时长）+ 可选字段
  - 此功能优先级：**v0.1 必须实现**（统一发布的核心组件）
- **证据**：`O1-Q5`、`O1-Q19`、`A1-Q1`
- **关联假设**：新发现（原 H 假设未覆盖）

### F-08 候补机制缺失，取消后重新招募成本极高

- **事实**：
  - O2 平均每次活动 2–3 人取消或缺席
  - 无候补机制 → 取消 = 回群里重新发"急招" → 补满平均耗时 2–3 小时
  - 活动前临时取消时（如活动前 3 小时），重新招募可能来不及
- **用户原话**：
  - O2：「招募时经常会有同学因为某些不可抗力因素退出，这个时候我们就需要"候补"，但是由于之前只是在微信群里发，所以总不能把还有意向的同学专门拉一个候补的小群吧，太麻烦了。所以只能当有同学退出后我们重新去群里再次招募所缺人数，很是麻烦」
  - O2：「希望有自动候补队列，有人取消就自动通知候补第一人，不用自己管」
- **团队推断**：
  - H4 已验证：候补自动补位是高频痛点，必须解决
  - 候补机制的核心是"锁定意向但不占名额"——报名即进入队列，有人取消自动递补
  - 此功能优先级：**v0.2 必须实现**（核心业务流程）
- **证据**：`O2-Q14`、`O2-Q15`、`O2-Q19`
- **关联假设**：H4 ✅ 已验证

### F-09 调研问卷发布渠道受限，样本不随机且数量不足

- **事实**：
  - O3 问卷目标 200 份，实际只收到 50 份（朋友圈 + 认识的群）
  - 样本偏同院同学，严重不随机
  - 最终因样本不够放弃了那次调研
- **用户原话**：
  - O3：「要是可以让所有目标都看到，且有一些"奖励机制"调动所有同学的积极性就好了」
- **团队推断**：
  - H1 的延伸问题：调研（尤其是问卷类）比志愿活动更依赖渠道——志愿活动有"名额紧迫感"驱动转发，问卷完全靠社交圈
  - 平台统一发布能解决"可见性"问题；奖励机制可能是加分项但需要预算
  - 此发现印证了 F-01（入口分散），是 H1 的具体实例
- **证据**：`O3-Q3`、`O3-Q19`
- **关联假设**：H1 ✅ 已验证（延伸实例）

| H7 | 用户不能始终停留在平台内，邀请、确认、取消和候补需要邮件等主动通知 | ✅ 已验证 | F-02 | S2（微信群无提醒错过名额） |
