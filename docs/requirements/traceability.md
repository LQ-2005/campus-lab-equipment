## 5. 缺口与待确认

1. `findings.md` 的 REQ 清单没有覆盖匿名候选池、审核举报和运营统计，但项目基线 README 的 v0.2、v0.3 已包含这些能力，因此本矩阵暂用「待补 REQ-17 ~ REQ-19」占位。
2. US-18、US-19 只有访谈证据、没有独立调研发现，暂标「待补 F-11」；US-23 来自项目基线设计决策，不属于调研结论。
3. REQ-06 的注册流程和三种角色的权限矩阵尚未展开，需要在架构设计阶段补用例。
4. 本矩阵只做到「证据 → 发现 → 故事 → 需求」，用例（UC）和测试用例（TC）在设计与测试阶段补全。

## 6. 维护规则

- 新增或删除用户故事时，必须同步更新本矩阵第 3、4 节。
- 需求条目编号一旦进入基线评审，不重排、不复用；作废的条目保留并标注状态。
- 每条用户故事至少保留一条证据来源；证据被推翻时，故事必须重新评审。
