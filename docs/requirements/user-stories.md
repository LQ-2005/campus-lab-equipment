## 3. 编写约定

- 每条故事包含：角色、目标、业务价值、关联调研发现、关联需求、增量归属。
- 验收标准统一使用 Given / When / Then，三要素齐全；一条验收标准只描述一个可观察结果。
- 每条故事至少关联一条调研发现（F-xx）；没有对应发现的，明确标注「待验证」或「项目基线设计决策」并说明证据来源。
- 业务价值不写功能名，只写解决了谁的什么问题。
- 用户故事只描述需求，不写实现方案（接口、表结构、框架选型不在本文档）。
- 需求编号统一为 REQ-01 ~ REQ-19 与 CAND-01，编号含义以本文件与 `traceability.md` 为准。

## 4.1 参与偏好

### US-01 维护个人偏好档案

- **角色**：参与者
- **目标**：一次填写兴趣、技能和可参与时段，之后长期复用
- **业务价值**：消除每次报名重复填写，减少因填写慢而错过名额（F-03，S3）
- **关联**：F-03｜REQ-03｜v0.1

**验收标准**

1. Given 参与者尚未填写档案，When 打开偏好设置，Then 显示兴趣、技能、可参与时段三个分区，并标明哪些必填。
2. Given 填写完整并保存，When 重新登录，Then 回显上次保存的内容。
3. Given 删除某个兴趣标签，When 保存成功，Then 该标签不再参与后续匹配。

### US-02 报名时复用已保存信息

- **角色**：参与者
- **目标**：报名时不必重新填写已经保存过的年级、专业、空闲时间和联系方式
- **业务价值**：把报名耗时从分钟级降下来，避免填写过程中名额被抢完（F-03，S3）
- **关联**：F-03｜REQ-03、REQ-08｜v0.2
- **说明**：v0.1 只做档案维护（US-01），报名信息复用依赖报名流程，随报名功能在 v0.2 交付。

**验收标准**

1. Given 参与者档案完整，When 点击某个活动的报名，Then 表单预填年级、专业、空闲时间和联系方式，且本次报名可单独修改。
2. Given 在报名表单中修改了预填值，When 提交报名成功，Then 档案中的值保持不变。
3. Given 档案缺少报名必填项，When 提交报名，Then 拒绝提交并提示需要补齐的字段。

## 4.2 机会发现

### US-03 无需加群浏览与检索全部机会

- **角色**：参与者
- **目标**：不依赖微信群也能看到全部在招的调研和志愿机会
- **业务价值**：解决新人不在群里就完全接触不到机会的问题（F-01，S1；F-09，O3）
- **关联**：F-01、F-09｜REQ-01、REQ-04｜v0.1

**验收标准**

1. Given 新注册的参与者，When 进入机会列表，Then 能看到全部已发布且未截止的调研与志愿机会。
2. Given 选择类型、时间范围或输入关键词，When 应用筛选，Then 列表只展示符合条件的机会。
3. Given 筛选条件没有任何匹配，When 应用筛选，Then 显示空状态提示，而不是报错或空白页。

### US-04 查看活动详情中的全部参与条件

- **角色**：参与者
- **目标**：在报名前看清资格、时间、地点、时长和物品要求
- **业务价值**：避免报名后才发现不符合条件，减少被刷或退出的尴尬（F-04，S4、O1）
- **关联**：F-04｜REQ-05｜v0.1

**验收标准**

1. Given 列表中任一活动，When 打开详情，Then 展示资格要求、具体时间段、地点、时长、服装或材料要求、剩余名额。
2. Given 组织者未填写某个必填字段，When 参与者打开详情，Then 详情页显示「未提供」，而不是留空或隐藏。
3. Given 活动已过报名截止时间，When 参与者打开详情，Then 详情页显示截止状态并禁用报名入口。

### US-05 用模板发布调研与志愿机会

- **角色**：组织者
- **目标**：用统一模板发布，不必每次从头写公告和报名表字段
- **业务价值**：降低发布成本，同时从源头保证关键信息不遗漏（F-07，O1；F-04，S4）
- **关联**：F-07、F-04｜REQ-02｜v0.1
- **说明**：问卷发布入口不属于本故事，由 US-25 单独承接（REQ-15）。

**验收标准**

1. Given 组织者选择「调研」或「志愿」模板，When 进入发布页，Then 显示该类型的必填字段清单（资格、时间、地点、时长等）。
2. Given 任一必填字段为空，When 提交发布，Then 拒绝发布并定位到缺失字段。
3. Given 发布成功，When 参与者查看详情，Then 展示内容与模板字段一一对应，没有多余字段。

## 4.3 匹配与邀请

### US-06 获得按资格与空闲时间匹配的机会

- **角色**：参与者
- **目标**：只看到自己符合条件、且时间不冲突的机会
- **业务价值**：把「翻完所有公告再判断自己行不行」变成系统先判断（F-04、F-03）
- **关联**：F-04、F-03｜REQ-07｜v0.2

**验收标准**

1. Given 参与者档案完整，When 打开「适合我的机会」，Then 只显示资格满足且可参与时段有交集的机会。
2. Given 某机会的资格不满足，When 参与者浏览匹配列表，Then 该机会不出现在列表中，但仍可在全量列表中检索到。
3. Given 某个机会与已确认的参与时间冲突，When 参与者浏览匹配列表，Then 该机会标注冲突原因。

### US-07 匿名候选池与定向邀请

- **角色**：组织者（发起方）、参与者（受邀方）
- **目标**：组织者能从符合条件的人里定向邀请，受邀者在接受前不暴露联系方式
- **业务价值**：提高招募命中率，同时避免在确认前公开个人信息（F-04、F-10，A2）
- **关联**：F-04、F-10｜REQ-07、REQ-17｜v0.2
- **说明**：v0.2 只保证邀请在平台内可见（「我的邀请」列表），不依赖 v0.3 的通知中心；站内与邮件提醒由 US-16、US-17 在 v0.3 承接。

**验收标准（组织者视角）**

1. Given 活动名额未满，When 组织者打开候选池，Then 只显示符合条件者的匿名摘要（年级、专业、技能标签），不显示姓名、手机号和微信号。
2. Given 组织者选中候选并发出邀请，When 邀请创建成功，Then 邀请出现在受邀者的「我的邀请」列表，并带有有效期。

**验收标准（参与者视角）**

3. Given 受邀者打开「我的邀请」，When 接受邀请，Then 直接生成报名并锁定名额，不需要重新填写档案。
4. Given 受邀者拒绝或邀请过期，When 系统处理该邀请，Then 名额释放，且不在受邀者侧留下任何负面记录。

## 4.4 报名与预约

### US-08 报名并锁定名额

- **角色**：参与者
- **目标**：提交报名后立即知道是否占到名额
- **业务价值**：避免「报了但不知道有没有报上」，也避免超员（F-03，S3）
- **关联**：F-03｜REQ-08｜v0.2

**验收标准**

1. Given 名额有剩余且资格满足，When 提交报名，Then 报名状态为已确认，剩余名额减 1。
2. Given 名额已满，When 提交报名，Then 拒绝报名并提示可以加入候补。
3. Given 两人同时争抢最后一个名额，When 两人都提交报名，Then 只有一人状态为已确认，另一人收到「名额已满」。

### US-09 取消报名

- **角色**：参与者
- **目标**：在活动开始前主动取消，把名额让出来
- **业务价值**：减少组织者临时缺人的情况（F-08，O2）
- **关联**：F-08｜REQ-08｜v0.2

**验收标准**

1. Given 报名已确认且活动尚未开始，When 取消报名，Then 状态变为已取消，名额立即释放。
2. Given 活动已经开始，When 尝试取消，Then 拒绝自行取消并提示联系组织者。
3. Given 取消成功且该活动存在候补队列，When 名额释放完成，Then 触发候补补位流程（见 US-11）。

## 4.5 取消与候补

### US-10 加入候补队列

- **角色**：参与者
- **目标**：名额满了也能排队，有人退出就按顺序补上
- **业务价值**：不用再盯着微信群等「急招」消息（F-08，O2）
- **关联**：F-08｜REQ-09｜v0.2

**验收标准**

1. Given 名额已满，When 点击「加入候补」，Then 进入队列并获得一个可见的排队序号。
2. Given 已在同一活动的候补队列中，When 再次点击加入，Then 提示已在队列中，不重复入队。
3. Given 参与者在候补队列中，When 主动退出候补，Then 从队列移除，后续候选人的序号相应前移。

### US-11 取消后自动补位

- **角色**：参与者（候补人）、组织者
- **目标**：有人退出时自动把名额给候补第一人，不需要组织者再去群里喊人
- **业务价值**：把补位从 2–3 小时的人工招募变成自动完成（F-08，O2）
- **关联**：F-08、F-02｜REQ-09｜v0.2
- **说明**：v0.2 的补位结果通过「我的报名」状态与名单同步呈现；站内与邮件提醒由 US-16、US-17 在 v0.3 提供。

**验收标准（参与者视角）**

1. Given 候补队列非空，When 一名已确认参与者取消报名，Then 系统按序号把第一顺位转为已确认。
2. Given 补位成功，When 该参与者打开「我的报名」，Then 该条记录显示为已确认。
3. Given 第一顺位在有效期内未确认，When 有效期到期，Then 系统顺延给下一顺位，并记录顺延原因。

**验收标准（组织者视角）**

4. Given 补位完成，When 组织者打开活动名单，Then 名单人数与状态已同步更新。

## 4.6 签到与完成

### US-12 签到并确认完成

- **角色**：组织者
- **目标**：活动现场能快速点名，活动结束后一次性确认谁完成了
- **业务价值**：把「纸质名单 + 事后回忆」变成可追溯的记录（F-05，S5）
- **关联**：F-05｜REQ-16｜v0.3

**验收标准**

1. Given 活动进行中，When 组织者打开签到名单，Then 只显示状态为已确认的参与者。
2. Given 组织者勾选某人到场，When 保存签到，Then 记录签到时间；未勾选者在活动结束后标记为缺席。
3. Given 活动结束，When 组织者提交完成确认，Then 只有已签到的参与者被记为完成，未签到者不产生完成记录。

### US-13 查看自己的完成状态

- **角色**：参与者
- **目标**：知道自己在某次活动中是已完成、缺席还是待确认
- **业务价值**：避免事后只能靠微信群公告判断自己算不算参与过（F-05，S5）
- **关联**：F-05｜REQ-16｜v0.3

**验收标准**

1. Given 活动已结束，When 打开「我的报名」，Then 每条记录显示已完成、缺席或待确认。
2. Given 组织者尚未确认，When 参与者打开「我的报名」，Then 显示「待组织者确认」，而不是空白。
3. Given 完成状态发生变化，When 参与者打开「我的报名」，Then 看到最新状态；主动提醒由 US-16 在 v0.3 提供。

## 4.7 参与记录

### US-14 查看统一参与记录

- **角色**：参与者
- **目标**：在一个地方看到自己参加过的全部调研和志愿活动
- **业务价值**：不用再翻微信群聊天记录回忆经历（F-05，S5）
- **关联**：F-05｜REQ-11｜v0.3

**验收标准**

1. Given 参与者有已完成记录，When 打开「我的参与记录」，Then 按时间倒序列出活动名称、类型、时间、担任角色和组织者。
2. Given 调研和志愿记录都有，When 打开「我的参与记录」，Then 两类出现在同一列表，并支持按类型筛选。
3. Given 没有任何记录，When 打开「我的参与记录」，Then 显示空状态和引导说明。

### US-15 引用参与记录

- **角色**：参与者
- **目标**：填写申请材料时能直接取用自己某条参与记录的摘要
- **业务价值**：把凑经历的时间从十几分钟降到一次复制（F-05，S5）
- **关联**：F-05｜REQ-11｜v0.3

**验收标准**

1. Given 选中某条参与记录，When 点击「生成摘要」，Then 输出活动名称、时间、角色、组织者的纯文本摘要。
2. Given 选择时间范围，When 导出，Then 文件只包含本人记录，不含其他参与者信息。
3. Given 记录对应的活动被组织者撤销，When 再次查看该记录，Then 该记录标注为已失效，但保留在历史中。

## 4.8 通知

### US-16 接收站内通知

- **角色**：参与者、组织者
- **目标**：报名、取消、候补递补和完成确认等关键事件能在平台内收到提醒
- **业务价值**：不再依赖「刷微信群」才能知道结果（F-02，S2）
- **关联**：F-02｜REQ-13｜v0.3

**验收标准**

1. Given 关键事件发生（报名确认、取消、候补递补、完成确认），When 事件处理成功，Then 相关方收到对应的站内通知。
2. Given 存在未读通知，When 打开平台任意页面，Then 通知入口显示未读数量。
3. Given 打开通知并标记已读，When 已读状态保存成功，Then 未读数量相应减少。

### US-17 邮件通知且失败不阻塞主流程

- **角色**：参与者、组织者
- **目标**：离开平台时也能通过邮件收到关键提醒，同时邮件出问题不影响报名结果
- **业务价值**：覆盖不常登录平台的用户；邮件故障不能被当成报名失败（F-02；A1-Q11）
- **关联**：F-02、A1-Q11｜REQ-13｜v0.3

**验收标准**

1. Given 用户开启邮件通知且邮箱已验证，When 关键事件发生，Then 通过 Outbox 异步发送邮件，主流程不等待发送结果。
2. Given 邮件服务不可用，When 触发关键事件，Then 报名、取消、候补事务照常提交，邮件进入待重试状态。
3. Given 同一事件被重复触发，When 该事件进入发送队列，Then 幂等键保证只发送一次。
4. Given 连续失败超过阈值，When 运营者打开发送记录，Then 能看到失败列表和失败原因。

## 4.9 平台治理与隐私

### US-18 审核活动与处理举报

- **角色**：平台运营者
- **目标**：发布前发现信息不全或疑似虚假的活动，并处理举报
- **业务价值**：防止冒充组织者骗取学生信息（A1-Q9），减少重复发布（A1-Q2）
- **关联**：待验证 F-11（A1-Q1、A1-Q2、A1-Q3、A1-Q9）｜REQ-18｜v0.3
- **证据状态**：证据直接来自 A1 访谈纪要，尚未在 `findings.md` 登记为正式发现，需在 findings 下一版补登 F-11 或补充访谈确认。

**验收标准**

1. Given 组织者提交发布，When 活动进入待审核状态，Then 运营者能看到模板字段完整性检查结果。
2. Given 信息不全或疑似虚假，When 运营者驳回，Then 组织者收到带原因的驳回通知，活动不对外展示。
3. Given 收到举报，When 运营者处理完成，Then 记录处理人、时间、结论，可回溯。
4. Given 两个活动内容高度相似，When 运营者审核新发布，Then 系统提示疑似重复发布，由运营者判断。

### US-19 查看去标识化运营统计

- **角色**：平台运营者
- **目标**：了解报名率、到场率和参与人群分布，但不看到具体是谁
- **业务价值**：支持运营决策，同时避免统计功能本身造成隐私泄露（A1-Q8、A2-Q8）
- **关联**：待验证 F-11（A1-Q8、A2-Q8）｜REQ-19｜v0.3
- **证据状态**：同 US-18，证据来自 A1、A2 纪要，待登记为正式发现。

**验收标准**

1. Given 选择时间范围，When 查询统计，Then 展示报名人数、到场率、活动类型分布和各年级参与比例。
2. Given 打开任一统计视图，When 页面加载完成，Then 不出现姓名、学号、手机号。
3. Given 某个维度的样本量小于设定阈值，When 查询该维度，Then 不展示该维度数值，避免反推个人。

## 4.10 隐私与数据访问

### US-20 控制联系方式可见范围

- **角色**：参与者、组织者
- **目标**：确认参与前不暴露手机号、微信号和家庭住址，确认后也只让组织者看到必要信息
- **业务价值**：避免名单被无关人员看到、被用来推销（F-10，A2-Q5、A2-Q6）
- **关联**：F-10｜REQ-12｜v0.3

**验收标准（参与者视角）**

1. Given 尚未确认参与，When 其他参与者查看活动详情或名单，Then 看不到手机号、微信号和家庭住址。
2. Given 已确认参与，When 其他参与者查看名单，Then 仍然看不到联系方式。

**验收标准（组织者视角）**

3. Given 已确认参与，When 该活动组织者查看名单，Then 只可见必要联系方式。
4. Given 活动结束超过设定的保留期，When 组织者查看该活动名单，Then 联系方式自动失效。

### US-21 名单导出需权限并留痕

- **角色**：平台运营者
- **目标**：导出名单必须有权并且能查到谁导出了什么
- **业务价值**：避免名单 Excel 被误发后无法追责（F-10，A2-Q4、A2-Q9）
- **关联**：F-10｜REQ-12｜v0.3

**验收标准**

1. Given 无导出权限，When 打开名单页面或直接调用导出接口，Then 不显示导出入口，接口返回 403。
2. Given 有权限，When 完成一次导出，Then 记录操作人、时间、字段范围和记录条数。
3. Given 访问不属于自己负责活动的名单，When 提交请求，Then 拒绝访问并写入审计日志。

## 4.11 预沟通、登录与基础权限

### US-22 在活动详情页提问

- **角色**：参与者
- **目标**：不用加组织者好友也能问清个性化问题
- **业务价值**：减少「不敢问就不报」和「问了被拒」的尴尬（F-06，S6）
- **关联**：F-06｜REQ-14｜v0.3

**验收标准**

1. Given 活动开放提问，When 提交问题，Then 问题出现在详情页，且不展示提问者的联系方式。
2. Given 组织者回复，When 回复发布成功，Then 提问者收到通知。
3. Given 活动报名已截止，When 参与者尝试提交新问题，Then 不再接受新问题，历史问答仍可查看。

### US-23 GitHub OAuth 登录

- **角色**：全部角色
- **目标**：用 GitHub 账号登录，不必再记一套密码
- **业务价值**：降低注册门槛（项目基线设计决策，见 `docs/04-external-integrations.md`；非访谈结论）
- **关联**：无对应发现｜REQ-10｜v0.2

**验收标准**

1. Given 未登录用户，When 选择 GitHub 登录，Then 跳转授权页，回调成功后建立会话。
2. Given 首次登录完成授权，When 进入平台，Then 要求补充角色和必要档案，未完成前不能报名。
3. Given 用户拒绝授权或回调失败，When 返回平台，Then 停在登录页并提示，不创建账号。
4. Given 授权账号邮箱不可见，When 系统尝试读取邮箱，Then 提示绑定邮箱或改用邮箱注册。

### US-24 按角色访问对应功能

- **角色**：全部角色
- **目标**：登录后只看到并只能调用自己角色范围内的功能
- **业务价值**：避免参与者误入运营功能、越权访问他人数据（项目基线权限要求，角色定义见 §2；非访谈结论）
- **关联**：无对应发现｜REQ-06｜v0.1

**验收标准**

1. Given 未登录用户，When 访问需要登录的页面或接口，Then 返回 401 并跳转登录页。
2. Given 参与者身份，When 调用组织者或平台运营者专属接口，Then 返回 403 并记录审计信息。
3. Given 平台运营者身份，When 访问运营接口，Then 正常返回结果。
4. Given 普通注册用户首次登录，When 尚未选择角色，Then 不能执行发布或报名操作。

### US-25 从机会详情进入外部问卷

- **角色**：参与者
- **目标**：从调研机会详情进入组织者提供的外部问卷
- **业务价值**：扩展问卷触达范围，同时由外部问卷服务处理答卷，平台不保存问卷题目和原始答案（F-09，O3）
- **关联**：F-09｜REQ-15｜v0.1
- **说明**：平台只保存外部问卷链接；奖励机制不在本故事范围内，见 CAND-01。

**验收标准**

1. Given 调研机会配置了有效的外部问卷链接，When 参与者打开详情，Then 显示「去填写外部问卷」入口。
2. Given 参与者点击外部问卷入口，When 浏览器完成跳转，Then 打开外部问卷页面，平台不接收或保存问卷答案。
3. Given 调研机会没有配置外部问卷链接，When 参与者打开详情，Then 不显示外部问卷入口。
