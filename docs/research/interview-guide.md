# 访谈与问卷提纲

## 1. 使用说明

本提纲用于 Issue #6 第二阶段的调研执行，配套文档为 `docs/01-research-plan.md`。

| 角色 | 提纲章节 | 预计时长 |
| --- | --- | --- |
| 学生 S1–S4 | 第 4 节 | 30–40 分钟 |
| 教师 T1 | 第 5 节 | 40 分钟 |
| 实验室管理员 A1 | 第 6 节 | 45 分钟 |
| 设备维修人员 M1 | 第 7 节 | 30 分钟 |

访谈要求：

- 采用半结构化方式，按提纲顺序提问，允许根据回答追问，但不能跳过核心问题。
- 提问以「最近一次具体经历」为主，避免让受访者评价抽象的「系统好不好」。
- 记录用户原话，标注问题号，例如 `[S1-Q3]`，便于后续追溯。
- 主访负责提问和追问，记录人负责原话、时间线和待确认问题，两人不得由同一人担任。

## 2. 开场与知情说明

每场访谈开始前统一说明，控制在 1 分钟内：

1. 本次访谈用于软件工程课程设计，目标是了解设备预约、使用和报修的真实流程。
2. 访谈内容只用于需求分析，不涉及对个人或部门的评价。
3. 记录中会去掉姓名、学号、工号和联系方式，统一使用代号。
4. 预计用时，是否同意开始记录；如需要录音会单独征得同意。
5. 受访者可以随时跳过某个问题或结束访谈。

不要向受访者展示已有方案或功能列表，避免诱导回答。

## 3. 提问与记录原则

| 原则 | 做法 | 反例 |
| --- | --- | --- |
| 问事实不问评价 | 「你上次预约是什么时候，怎么约的」 | 「你觉得现在的预约流程方便吗」 |
| 一次只问一个问题 | 拆成具体小问题 | 「预约和报修有什么问题」 |
| 追问到具体动作 | 连续追问「然后呢」「当时在哪里看到的」 | 停在「很麻烦」 |
| 区分事实与原话 | 事实记时间线，原话加引号 | 把推断写进原话 |
| 不预设答案 | 提供选项前先让受访者自由描述 | 「是不是因为没有通知功能」 |
| 记录反例 | 与假设矛盾的证据同样记录 | 只挑符合假设的内容 |

常用追问：

- 「能具体讲一次最近发生的例子吗？」
- 「当时你最先做了什么？之后呢？」
- 「这个环节大概花了多久？」
- 「如果这一步没做成，最后怎么处理的？」
- 「除了你，还有谁参与了这个流程？」

## 4. 学生访谈提纲（S1–S4）

### 4.1 背景与使用情况（Q1–Q4）

- Q1 你目前接触过哪些实验室或实验设备？使用频率大概是多久一次？
- Q2 最近一次使用实验室设备是什么时候，用来完成什么任务？
- Q3 你通常和谁一起使用设备，是否需要组队或课程安排？
- Q4 你使用设备的资格是如何获得的，是否需要培训或授权？

### 4.2 现状流程（Q5–Q10）

- Q5 请按时间顺序讲一次完整的预约过程：从哪里得知设备信息，怎么确认空闲，怎么提交申请。
- Q6 设备是否空闲，你是通过什么渠道确认的？群聊、表格、老师还是现场看？
- Q7 提交预约需要提供哪些信息？向谁提交？
- Q8 提交之后多久能得到答复？答复通过什么方式通知你？
- Q9 预约成功后，使用当天需要做什么？是否需要签到、登记或找管理员开门？
- Q10 使用结束后需要做什么记录或归还动作？

### 4.3 痛点与异常场景（Q11–Q16）

- Q11 最近一次预约失败或被拒绝是什么情况，原因是什么？
- Q12 是否遇到过设备在预约时段被他人占用或重复预约？当时怎么解决？
- Q13 是否遇到过设备临时故障或维修，原预约怎么处理？
- Q14 如果需要取消或改期，你的操作流程是什么，有没有产生误会？
- Q15 有没有出现过忘记使用或迟到导致时段浪费的情况？怎么处理的？
- Q16 整个流程中，哪一步最费时间或最容易出错？请举一个具体例子。

### 4.4 期望与优先级（Q17–Q20）

- Q17 如果只能改一件事，你最希望改哪一件？为什么？
- Q18 你希望在什么时间点收到提醒？例如提交后、审批后、使用前一天、维修完成。
- Q19 你是否需要查看自己的历史预约和使用记录？用来做什么？
- Q20 对设备报修，你希望提交哪些信息？是否愿意上传照片？

### 4.5 收尾（Q21–Q22）

- Q21 还有什么我们没问到但你觉得重要的情况？
- Q22 是否可以推荐 1 位有类似经历的同学参与访谈？

## 5. 教师访谈提纲（T1）

### 5.1 背景（Q1–Q3）

- Q1 您负责哪些课程或实验室，需要审批哪类设备使用？
- Q2 一个学期大概处理多少次设备预约审批？
- Q3 审批权限的范围是如何划定的，有哪些设备需要额外审批？

### 5.2 现状流程（Q4–Q9）

- Q4 学生通过什么方式向您提出预约申请？需要提供哪些信息？
- Q5 您审批时主要看哪些条件？时段冲突、人数、资格、安全要求还是用途？
- Q6 您如何确认该时段设备确实空闲？信息来源是什么？
- Q7 审批结果如何告知学生？如果学生没看到通知会怎样？
- Q8 出现时段冲突时，您通常怎么协调？有没有优先级规则？
- Q9 设备维修或停用期间，您如何处理已经批准的预约？

### 5.3 痛点与风险（Q10–Q15）

- Q10 审批过程中最耗时的环节是什么？请举一个具体例子。
- Q11 有没有出现过重复批准或批准后设备不可用的情况？
- Q12 学生爽约或超时使用，您如何处理？是否有记录？
- Q13 您是否需要了解设备的使用记录和故障历史？用于什么决策？
- Q14 出过安全问题或设备损坏时，责任如何追溯？
- Q15 现有流程中哪些信息是缺失的，导致您无法判断？

### 5.4 期望（Q16–Q19）

- Q16 您希望在审批界面直接看到哪些信息？
- Q17 您希望系统提供哪些提醒？提醒对象和时机分别是什么？
- Q18 是否需要批量审批、代理审批或委托他人处理？
- Q19 对统计报表，您最关心哪些指标？

## 6. 实验室管理员访谈提纲（A1）

### 6.1 背景与台账（Q1–Q5）

- Q1 您负责的实验室有多少台设备？大致分几类？
- Q2 设备台账目前记录在什么地方？包含哪些字段？
- Q3 设备状态（可用、维修、停用、报废）如何记录和更新？
- Q4 设备维护周期和到期提醒目前怎么管理？
- Q5 一台设备从采购到报废，大致经历哪些状态变化？

### 6.2 预约与审批（Q6–Q10）

- Q6 学生预约主要通过什么方式提交？您如何审批？
- Q7 同一时段多个申请时，您的处理规则是什么？
- Q8 您如何避免两台设备或两个申请之间的冲突？
- Q9 审批通过后，使用当天您需要做哪些准备和登记？
- Q10 学生未到场或超时，您如何记录和处理？

### 6.3 使用与报修（Q11–Q16）

- Q11 使用登记目前记录哪些内容？由谁填写？
- Q12 设备故障由谁发现、如何上报？报修信息通常包含什么？
- Q13 报修后如何判断设备是否需要停用？谁来决策？
- Q14 维修过程如何跟踪？维修完成后如何验收并恢复可用？
- Q15 维修期间受影响的预约如何处理？是否会通知相关人？
- Q16 是否有维修历史记录？查询历史时依靠什么？

### 6.4 痛点与期望（Q17–Q22）

- Q17 日常工作中最耗时的环节是什么？请举一个具体例子。
- Q18 有没有因为信息不一致导致设备被重复预约或错误停用？
- Q19 您需要哪些统计信息？例如使用率、故障率、维修时长。
- Q20 哪些操作必须留下操作人和时间记录？为什么？
- Q21 如果系统上线，您最担心哪类误操作？希望如何防止？
- Q22 对移动端或现场扫码登记，您是否有需求？

## 7. 设备维修人员访谈提纲（M1）

- Q1 您接收报修的方式是什么？报修单通常包含哪些信息？
- Q2 哪些信息缺失会导致您无法判断故障或准备工具？
- Q3 从接单到修复完成，中间有哪些状态？谁来更新？
- Q4 维修期间设备是否会被误用？如何标记？
- Q5 维修完成后由谁验收？验收标准是什么？
- Q6 备件和维修记录如何保存？需要查询历史故障吗？
- Q7 最希望系统提供哪些信息或提醒？

## 8. 流程观察与还原脚本

选择一次真实或还原的「预约—审批—使用—报修」流程，记录以下内容：

| 观察项 | 记录要求 |
| --- | --- |
| 触点 | 每一步通过什么渠道完成：群聊、电话、纸质表、Excel、当面 |
| 参与人 | 学生、教师、管理员、维修人员分别在哪一步介入 |
| 输入输出 | 每一步需要提供什么信息，产生什么记录 |
| 耗时 | 每一步的等待时间和操作时间 |
| 交接 | 信息从一个人传到另一个人时是否有丢失或重复录入 |
| 异常分支 | 冲突、取消、设备故障时的实际处理路径 |

观察结论写入 `docs/research/findings.md` 的现状流程章节，并标注证据来源。

## 9. 问卷提纲

### 9.1 用途与发放

- 对象：使用实验室设备的在校学生。
- 目的：量化验证访谈中发现的痛点频率和优先级，不作为访谈替代。
- 方式：匿名线上问卷，目标有效回收不少于 20 份。
- 不收集姓名、学号、手机号和具体班级。

### 9.2 题目结构

| 区块 | 题量 | 题型 | 示例 |
| --- | --- | --- | --- |
| 使用情况 | 3 | 单选 | 本学期使用实验室设备的频率：从未 / 1–2 次 / 3–5 次 / 5 次以上 |
| 预约方式 | 3 | 单选、多选 | 你通常通过哪些方式确认设备空闲：群聊询问 / 查看表格 / 询问老师 / 现场查看 |
| 等待与答复 | 2 | 单选 | 提交预约后通常多久收到答复：当天 / 1–2 天 / 3 天以上 / 没有固定答复 |
| 异常经历 | 4 | 多选、单选 | 你是否遇到过设备被重复预约：经常 / 偶尔 / 从未 |
| 痛点排序 | 1 | 排序题 | 按困扰程度排序：信息不透明、审批慢、冲突、取消麻烦、报修无反馈 |
| 期望功能 | 1 | 多选 | 最希望优先实现：实时空闲查询 / 在线预约 / 审批通知 / 使用登记 / 报修跟踪 |
| 开放题 | 1 | 填空 | 请描述一次最不顺利的设备使用经历（选填，不要填写个人信息） |

### 9.3 发放与统计

- 发放前由冯昊天自测题目，避免引导性选项和重复题。
- 统计只保留汇总结果，开放题中的个人信息需删除后再引用。
- 有效样本判定：完成全部必答题且使用频率不为「从未」。
- 统计结果写入 `docs/research/findings.md` 的问卷章节，并注明回收数、有效数和回收时间。

## 10. 纪要记录模板

每场访谈新建 `docs/research/notes/<代号>.md`，使用以下结构：

```markdown
# 访谈纪要：S1

## 元信息

- 角色：学生
- 日期：2026-11-19
- 时长：35 分钟
- 方式：线下
- 主访：冯昊天
- 记录：付艺豪
- 是否录音：否

## 使用背景

（年级泛化描述、使用频率、接触设备类型）

## 现状流程

（按时间顺序记录，不加入评价）

## 痛点与原话

- [S1-Q11] 「原话摘录」
  事实：当时发生了什么
  影响：造成了什么结果

## 异常场景

（冲突、取消、故障等具体经历）

## 期望

（受访者主动提出的期望，标注是否被追问确认）

## 待确认问题

- 需要补充访谈或向他人核实的问题

## 记录人备注

- 记录偏差、访谈中断、环境干扰等
```

记录要求：

- 事实用陈述句，原话加引号并标注问题号，推断单独标注为「推断」。
- 不确定的内容写入待确认问题，不得补写成结论。
- 访谈结束后 24 小时内完成，主访复核后提交。

- [ ] 所有纪要已去除姓名、学号、工号和联系方式。
- [ ] 每条发现都能对应至少一条证据编号。
- [ ] 事实、原话、推断三类内容已分别标注。
- [ ] 与假设矛盾的证据已保留并说明。
- [ ] 问卷有效样本数和统计口径已记录。
- [ ] 用户故事与调研发现的追溯关系已建立。
